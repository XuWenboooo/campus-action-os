# API contract

Every response includes `x-request-id`. Errors use `{ "error": { "code", "message", "requestId", "retryable" } }`. State-changing POST and PATCH operations require `Idempotency-Key`; a replay returns the original response, while reuse with a different request is a `409 IDEMPOTENCY_CONFLICT`. Soft-deleting a document, confirming/rejecting an action, completing a task, publishing/revoking/postponing a notice, linking a notice to a task, and resolving a notice-task sync event all require an explicit confirmation body. Development login is available only outside `APP_ENV=production`.

The executable route surface is implemented in `services/api/src/server.ts`; the core proof covers login/profile, document creation/upload/read/delete, parse jobs, actions, tasks, notices, notice-task synchronization and feedback. `POST /tasks/:taskId/notices` links a confirmed Task to the latest published revision. Later published, postponed or revoked revisions appear at `GET /tasks/:taskId/notice-sync` as `pending_review`; `POST /tasks/:taskId/notice-sync/:syncEventId/resolve` records the user's accept/reject decision. Accepting a revocation cancels only a pending or in-progress Task.
