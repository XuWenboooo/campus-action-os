# Security and privacy

All checked-in examples and fixtures are synthetic. No production endpoint or real key is used. User text is stored only in the local database selected by `DATABASE_PATH`; runtime database files are ignored. Production disables development login. Request IDs and audit events support traceability, while parser and HTTP logs must not print source text, tokens or secrets.

Production mode rejects development identity headers for protected routes until a real identity provider is configured. Local publisher access requires an explicit development role selection; this is not production authentication. Destructive document deletion and other externally meaningful actions require an explicit confirmation body; retries use scoped idempotency keys. Media upload bytes are bounded, checked against the declared PNG/JPEG/PDF signature, kept in the local ignored SQLite file, integrity-checked on read, and sent only to the explicitly selected local or injected OCR provider; no live provider is called by the test suite.
