# Testing

Use `npm.cmd run typecheck`, `npm.cmd run check:miniapp`, `npm.cmd run test`, `npm.cmd run test:api`, `npm.cmd run test:e2e`, `npm.cmd run db:migrate`, `npm.cmd run format:check`, `npm.cmd run lint`, and `npm.cmd run scan:secrets`. The core API test exercises the real parser HTTP server, SQLite repository, confirmation boundary and task state machine; it also covers parser outage → retained Document → explicit manual task fallback with idempotency and audit persistence. The stability E2E repeats the synthetic Document → ParseJob → VerifiedActionObject → confirmed Task → completed Task path 100 times. Completing a task and publishing a notice also require an explicit confirmation field. Error Shield and shared protocol tests intentionally cover missing or dangling evidence, unsafe deadlines, conflicting task states, unsupported claims, graph consistency and side-effect blocking. The mini-program check is static syntax/manifest validation only; runtime behavior remains `MANUAL_VERIFICATION_REQUIRED` until verified in WeChat Developer Tools.

`npm.cmd run evaluate:fixtures` uses only the 30 development-only synthetic notifications. Where a special audience is expected to be relevant, the fixture carries an explicit synthetic profile; multi-action counts and first-action evidence spans are annotated in the fixture itself. These numbers are development diagnostics, not the frozen 800-sample CampusActionBench result.
